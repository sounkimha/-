# 국장·미장 자동매매 학습 시스템

설정 파일 하나가 전략 하나입니다. 같은 엔진(데이터 수집 · 백테스트 · 손실 제한)을 씁니다.

| 프로필 | 설정 파일 | 대상 · 주문 | 실데이터 결과 (2026-10-01 실행) |
|---|---|---|---|
| **1시간봉 ML 단타** | `config.yaml` | 대형주 6종목(국장 3 · 미장 3), 한국투자증권 모의투자 자동 주문(`trade`) | 비용을 못 넘음: 국장 −8.6% vs 단순보유 +291%, 미장 −9.5% vs +42% → 연구용 |
| **일봉 ETF 추세** | `config.daily.yaml` | 국내 ETF 9종 · 100만원, 다음 거래일 **시가 주문표** → MTS 에 직접 입력. 가상계좌·모의투자 `trade` | KODEX 200 보유보다 수익 낮고 낙폭 작음 → [결과](#백테스트-결과-2026-10-01-실행) |

**1시간봉 ML**: 국내주식과 미국주식의 1시간봉으로 차트 특징값을 만들고, 머신러닝 분류 모델로
**"다음 봉이 왕복 비용(수수료·세금·슬리피지)보다 더 오를 확률"** 을 예측합니다.
확률과 비용 차감 기대수익이 기준을 넘을 때만 매수하고, 손실 제한 규칙 안에서 매매합니다.

**일봉 ETF**: 전날 종가로만 판단하는 추세 돌파 규칙입니다. 장중에 화면을 볼 필요가 없고, 주문은 다음 날 08:30~09:00 시가 동시호가에 냅니다.
자세한 내용은 [일봉 ETF 프로필](#일봉-etf-프로필-100만원--다음-날-시가-주문)을 보세요.

> ⚠️ **손실은 0으로 만들 수 없습니다.** 이 시스템이 하는 일은 손실을 *제한*하는 것입니다.
> 백테스트 결과는 미래 수익을 보장하지 않습니다. 실전 투입 여부는 아래 [단계별 진행 방법](#단계별-진행-방법)을 끝까지 거친 뒤 직접 판단하세요.

**안전장치 요약**
- `DRY_RUN` 기본값 `true`: `.env`에서 직접 `false`로 바꾸기 전에는 주문을 **절대 전송하지 않습니다** (미설정·오타도 `true`로 취급).
- 접속 서버는 **한국투자증권 모의투자 서버만** 허용합니다. 실전 서버 주소와 실전 tr_id(`T`로 시작)는 코드에서 거부합니다.
- API 키·시크릿·계좌번호는 `.env`에만 둡니다. `.env`는 `.gitignore`에 들어 있고, 저장소에는 `.env.example`만 있습니다.

## 설치

Python 3.11 기준으로 확인했습니다.

```bash
git clone https://github.com/sounkimha/-.git autotrader && cd autotrader
python3 -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env               # 모의투자 단계에서만 채우면 됨 (백테스트에는 필요 없음)
python -m pytest                   # 전부 passed 인지 확인
```

데이터는 Yahoo Finance(yfinance)에서 받습니다. **야후의 국장 1시간봉은 09:00~14:00 6봉이고 15:00~15:30(종가 동시호가 포함)이 없습니다**
(2026-10 확인: 1시간봉 거래량 합이 일봉의 대체로 70~85%, 14:00봉 종가 ≠ 실제 종가). 그래서 `config.yaml`의 국장 `session.close`를 15:00으로 두고,
국장은 14:00봉 시가에 장마감 청산하며 15:00 이후에는 주문하지 않습니다. 미장은 09:30~15:30 7봉으로 정규장 전체가 들어 있습니다.

사내망·클라우드 등 아웃바운드가 제한된 환경이면
`fc.yahoo.com`, `guce.yahoo.com`, `query1.finance.yahoo.com`, `query2.finance.yahoo.com` 접근이 허용돼야 합니다.

## 실행

```bash
python main.py fetch                      # 시세 수집 → data_cache/ (1시간봉 최근 729일)
python main.py backtest                   # 워크포워드 학습 + 백테스트 (국장·미장)
python main.py backtest --market kr       # 국장만
python main.py backtest --offline         # 네트워크 없이 캐시로
python main.py signal                     # 최신 완성 봉 기준 종목별 상승확률 / 매수·관망
python main.py trade --market kr          # 매매 1회 (DRY_RUN 기본 → 가상계좌에만 기록)
python main.py broker-check               # 모의투자 토큰·현재가·잔고 조회만 (주문 없음)

python main.py --config config.daily.yaml backtest   # 일봉 ETF 프로필 (아래 '일봉 ETF 프로필' 참고)
python main.py --config config.daily.yaml signal     # 다음 거래일 시가 주문표
python main.py --config config.daily.yaml trade --market kr   # 가상계좌 정산·계획 (DRY_RUN) / 모의투자 주문·확인
```

### backtest 출력 읽는 법

| 열 | 의미 |
|---|---|
| 전략수익%(계좌) | 그 종목 매매로 번 돈 ÷ 계좌 시작금액 (1회 20%만 투입되므로 작게 나옴). 마지막 줄(계좌 합계)은 계좌 전체 수익률 |
| 전략수익%(투입금) | 그 종목의 거래 수익률을 복리로 곱한 값 = 거래마다 배정액 전부를 넣었다면의 수익률. **종목별로 단순보유와 비교할 때는 이 열을 봅니다** |
| 단순보유% | 같은 기간 첫 봉 시가에 사서 끝까지 들고 있었을 때 (왕복 비용 반영, 100% 투입). 계좌 합계 줄은 종목 동일가중 |
| 거래수 / 승률% / 평균손익% | 청산된 거래 기준. 평균손익은 비용 차감 후 1회 수익률 |
| 최대낙폭%(전략 / 보유) | 전략: 계좌 시작금액+그 종목 누적손익 곡선의 MDD (합계 줄은 계좌 MDD). 보유: 단순보유 곡선의 MDD |

- 표 아래에 **평균 투입비중**, **청산 사유**(신호약화·손절·갭손절·장마감 청산·매매중단 청산), **모델 표본 외 AUC / 기저율 / 신호 적중률**, 그리고 **전략 vs 단순보유 판정**(계좌 합계는 계좌 수익률 vs 동일가중 단순보유, 종목별은 투입금 기준 vs 단순보유)이 나옵니다.
- 전략은 1회 계좌의 20%만 넣고 장중에만 보유하므로, 상승장에서는 단순보유(100% 투입)보다 수익이 낮게 나오는 게 정상입니다. 수익 크기만 보지 말고 **비용 차감 평균손익 > 0 인지, 모델 AUC가 0.5보다 의미 있게 높은지, 거래 수가 충분한지**를 같이 보세요.
- 결과 CSV(요약·거래내역·자산곡선)는 `reports/`에 저장됩니다.
- 일봉 규칙(`rule_breakout`)은 표 아래에 **같은 기간 비교표**(전략 / 비용 2배 / 기준 ETF 보유 / 동일가중 보유의 총수익·연환산·최대낙폭·샤프),
  **연도별 표**, **시장 국면별 표**(KODEX 200 의 200일선과 그 기울기로 상승·횡보·하락 구분)가 더 나옵니다.
  계좌 낙폭 한도에 걸려 중간에 멈췄다면 그 뒤로는 현금뿐이므로, 규칙의 성격을 보도록 "MDD 중단 없이 계속" 결과를 함께 보여 줍니다.

## 전략·학습 로직

**라벨**: `y_t = 1 ⇔ (t+1 봉 종가 / t+1 봉 시가 − 1) > 왕복비용`. t 봉 종가에서 신호를 보고 t+1 봉 시가에 진입하는 실제 순서와 맞췄습니다.

**특징값** (t 봉 종가까지의 정보만 사용): 1·2·4·8·24봉 수익률, RSI(14), 5·20·60봉 이동평균 대비 위치와 5/60 이평 비율, 8·24봉 변동성, 거래량/20봉 평균, 봉 몸통·윗꼬리·아랫꼬리·고저폭, 갭(직전 종가 대비 시가), 장중 몇 번째 봉인지·당일 누적수익률·시각, 최근 24봉 고가/저가 대비 위치. 창 길이는 `config.yaml`의 `features`에서 바꿉니다.

**모델**: 기본 `HistGradientBoostingClassifier`(깊이 3, 강한 규제). `model.type`으로 `logistic`, `random_forest` 선택 가능. 기본은 같은 시장 3종목을 합쳐 하나의 모델로 학습(`pooled: true`).

**워크포워드** (미래 정보 차단):
1. 거래일을 시간순으로 나눕니다. 처음 `min_train_days`(180거래일)는 학습만 하고 예측·매매하지 않습니다.
2. 이후 `retrain_every_days`(5거래일)마다: 그 구간 시작 **전에 라벨이 확정된** 데이터로만 새로 학습 → 그 구간을 예측.
3. 라벨이 다음 봉에 의존하므로, 라벨 봉 시작 시각(`label_time`)이 테스트 시작 이후인 샘플은 학습에서 뺍니다.
4. 백테스트와 성과표는 이 표본 외 예측 구간만 사용합니다.

`tests/test_features.py`는 "앞부분만 잘라 계산한 특징값 = 전체로 계산한 값", "미래 봉을 바꿔도 과거 특징값 불변"을, `tests/test_model.py`는 모든 폴드에서 `학습 라벨 시각 < 테스트 시작`을 검증합니다.

**매매 규칙** (`strategy`):
- 진입: 상승확률 ≥ `entry_threshold`(0.50) **그리고** 비용 차감 기대수익 ≥ `min_expected_return_pct`(0%).
  기대수익 = p·E[r | 상승] + (1−p)·E[r | 비상승] − 왕복비용 (조건부 평균은 학습 구간에서 계산). 확률이 0.5를 넘어도 기대수익이 음수면 사지 않습니다.
- 보유 중: 상승확률 < `exit_threshold`(0.45)이면 다음 봉 시가에 청산.
- 장마감 청산(`flatten_at_session_end: true`): 다음 봉이 그날 마지막 봉이면 그 시가에 청산하고, 마지막 봉 신규 진입은 하지 않습니다 → 오버나이트 보유 없음.

## 손실 제한 (`risk`, 모두 config.yaml에서 수정)

| 항목 | 기본값 | 동작 |
|---|---|---|
| `stop_loss_pct` | 1.0 | 진입 체결가 대비 −1%에 손절. **갭하락으로 시가가 손절가 아래면 그 시가에 청산 → −1%보다 더 손실** (백테스트에 반영) |
| `position_size_pct` | 20.0 | 1회 투입 = 계좌 평가금액의 20% (체결금액+수수료 기준, 정수 주식) |
| `max_drawdown_pct` | 10.0 | 계좌 고점 대비 −10% 도달 → 전체 신규 매매 중단 + (`liquidate_on_halt`) 보유분 청산. 자동 재개하지 않음 |
| `max_trades_per_day` | 4 | 시장별 계좌의 하루 신규 진입 횟수 한도. 청산·손절 매도는 제한 없음 |

실매매에서 매매 중단 상태는 `state/trade_state_<시장>_<모드>.json`(모드: `paper`=DRY_RUN 가상계좌, `vts`=모의투자)의 `risk.halted`에 저장됩니다. 원인을 확인한 뒤 `python main.py trade --market kr --resume`으로 재개합니다 (중단을 풀고 고점 기준을 그때 평가금액으로 다시 잡음 — `halted`만 `false`로 바꾸면 옛 고점 대비 낙폭이 그대로라 다음 실행에서 바로 다시 멈춥니다). 두 모드의 상태는 섞이지 않고, 모의투자의 낙폭 기준(고점)은 첫 잔고 조회값에서 시작합니다.

## 백테스트 가정

- 시장별(국장 KRW, 미장 USD) 계좌 1개에 종목 3개. 시작금액은 `initial_capital`.
- 신호는 봉 종가에 계산 → **다음 봉 시가에 체결** (매수 시가×(1+슬리피지), 매도 ×(1−슬리피지)).
- 손절: 봉 안의 가격 경로를 모르므로, 저가가 손절가에 닿으면 손절가에 체결 (같은 봉 안에서 손절이 먼저 일어났다고 보는 보수적 가정). 진입한 봉에서도 손절될 수 있음.
- 비용 기본값 (`markets.*.costs`, 단위 %):

  | | 편도 수수료 | 매도세 | 편도 슬리피지 | 왕복 합계 |
  |---|---|---|---|---|
  | 국장 | 0.015 | 0.20 | 0.01 | **0.25** |
  | 미장 | 0.04 | 0 | 0.01 | **0.10** |

  국장 매도세 0.20%는 2026년 1월 1일 양도분부터의 세율입니다 (코스피 거래세 0.05% + 농특세 0.15%, 코스닥 0.20%).
  세율은 세법 개정으로 바뀌므로 해마다 확인하세요. 수수료 0.015%는 온라인 수수료 수준으로 잡은 값이라 본인 계좌 기준으로 고치세요.
  미장 수수료는 계좌·이벤트에 따라 훨씬 높을 수 있고(예: 편도 0.25%), 환전 스프레드는 포함하지 않았습니다. **본인 계좌의 실제 비용으로 바꿔서 다시 돌려 보세요.**
- 기간 마지막에 남은 포지션은 마지막 종가에 청산(비용 반영).

## 주문 연결 (한국투자증권 Open API, 모의투자 전용)

엔드포인트·tr_id는 한국투자증권 공식 GitHub [`koreainvestment/open-trading-api`](https://github.com/koreainvestment/open-trading-api)
(`examples_llm`, 2026-09-28 커밋 `277ec0e`)에서 확인했습니다. `apiportal.koreainvestment.com`은 작업 환경에서 접속이 막혀 있어 직접 열어보지 못했습니다.

| 용도 | 메서드 · 경로 | 모의 tr_id |
|---|---|---|
| 접근토큰 | POST `/oauth2/tokenP` | – (유효 1일, 발급 시 알림톡) |
| 국내 주문(현금) | POST `/uapi/domestic-stock/v1/trading/order-cash` | 매수 `VTTC0012U` / 매도 `VTTC0011U` |
| 국내 잔고 | GET `/uapi/domestic-stock/v1/trading/inquire-balance` | `VTTC8434R` |
| 국내 현재가 | GET `/uapi/domestic-stock/v1/quotations/inquire-price` | `FHKST01010100` |
| 미국 주문 | POST `/uapi/overseas-stock/v1/trading/order` | 매수 `VTTT1002U` / 매도 `VTTT1001U` ※ |
| 미국 잔고 | GET `/uapi/overseas-stock/v1/trading/inquire-balance` | `VTTS3012R` |
| 미국 매수가능금액 | GET `/uapi/overseas-stock/v1/trading/inquire-psamount` | `VTTS3007R` |
| 미국 현재가 | GET `/uapi/overseas-price/v1/quotations/price` | `HHDFS00000300` |

- 모의투자 서버: `https://openapivts.koreainvestment.com:29443`. 호출 간격 0.5초(공식 예제의 모의투자 설정).
- 국내 주문은 기본 시장가(`ORD_DVSN=01`). `broker.domestic.order_type: limit`이면 현재가±0.3%를 호가단위에 맞춘 지정가.
- 미국 모의투자는 지정가(`00`)만 가능 → 현재가±0.3% 지정가로 냅니다. 미체결될 수 있습니다.
- ※ **미국 매도 모의 tr_id 불일치**: API 설명·Postman 모의계좌 샘플은 `VTTT1001U`, 공식 예제 코드의 자동변환(T→V)은 `VTTT1006U`를 만듭니다. 문서 값 `VTTT1001U`를 기본으로 썼습니다. 모의투자에서 매도가 tr_id 오류로 거부되면 `config.yaml`의 `broker.tr_id.overseas_sell`만 바꾸세요.
- tr_id가 바뀌면 `config.yaml`의 `broker.tr_id`만 수정하면 됩니다 (`V`로 시작하지 않으면 거부).

### trade 명령의 동작 (봉마다 1회 실행 전제)
1. 최신 **완성** 봉까지 데이터를 새로 받아 → 모델 학습 → 종목별 상승확률
2. 계좌 평가 → 최대낙폭 확인 → 보유 종목 청산 판단(매매중단·손절·장마감·신호약화) → 신규 진입 판단(신호·일일 한도·예산)
   - **장마감 청산은 시계 기준**으로도 판단합니다: 지금이 그날 마지막 봉 구간이면 데이터가 늦어도 전량 청산하고 신규 진입하지 않습니다.
   - 지금쯤 와 있어야 할 봉이 데이터에 없으면(지연·누락) 그 종목은 **신규 진입을 보류**합니다. 청산 판단은 계속합니다.
   - 시세를 못 받은 보유 종목은 마지막으로 알려진 가격으로 평가하고, 신호가 없으니 보수적으로 청산합니다.
3. `DRY_RUN=true`: 증권사로 아무것도 보내지 않고 `state/`의 가상계좌에 기록 (체결가 = 진행 중인 봉까지 포함한 최근 가격)
   `DRY_RUN=false`: 모의투자 서버로 주문. 잔고는 증권사 조회값, 이 시스템이 연 포지션만 관리(손절가는 `state/`에 기록)
   - 주문 **접수 ≠ 체결**로 다룹니다. 매수는 다음 사이클에 증권사 잔고에 나타나야 추적을 이어가고, 매도는 잔고에서 사라질 때까지 추적합니다.
     매도 주문이 아직 걸려 있으면(주문가능수량 0) 중복 매도하지 않고 기다립니다.
   - 응답을 못 받은 주문(타임아웃 등)은 '접수 여부 불명'으로 기록하고 다음 사이클에 잔고로 확인합니다.
   - 중간에 예외가 나도 그때까지의 상태·주문 기록은 저장됩니다.
4. 장 운영시간이 아니면 주문하지 않습니다 (`--ignore-hours`는 DRY_RUN에서만 동작).

## 단계별 진행 방법

### 1단계 — 백테스트 (지금)
```bash
python main.py fetch && python main.py backtest
```
다음을 **모두** 만족하지 않으면 2단계로 가지 않습니다 (기준은 예시이며 본인이 정하세요).
- 모델 표본 외 AUC가 0.5보다 의미 있게 높다 (예: 0.53 이상). 0.50 근처면 예측력이 없는 것.
- 시장별 거래 수가 충분하다 (예: 50회 이상). 몇 번 안 되는 거래의 수익은 운입니다.
- 비용 차감 **평균손익 > 0**, 계좌 MDD가 한도(−10%)보다 충분히 작다.
- 비용을 올려도(예: 미장 왕복 0.5%) 버티는지 확인한다.
- **같은 기간으로 임계값·파라미터를 반복 조정하지 않는다** (과최적화). 조정했다면 그 뒤 새로 쌓인 기간(모의투자)으로만 다시 평가합니다.

### 2단계 — 모의투자 2~3개월
1. 한국투자증권에서 **모의투자** 계좌와 모의투자용 앱키/시크릿 발급 → `.env`에 입력 (`DRY_RUN=true` 유지).
2. `python main.py broker-check` → 토큰 발급, 현재가, 잔고 조회가 되는지 확인 (주문 없음).
3. 1~2주: `DRY_RUN=true`로 `trade`를 매 봉마다 실행 → 가상계좌(`state/`)와 로그로 동작 확인.
4. 이후 `.env`에서 직접 `DRY_RUN=false` → 모의투자 서버로 주문. 2~3개월 운영.
5. 매주 기록: 거래 수, 미체결(특히 미장 지정가), 주문 기준가 대비 체결가 차이(실제 슬리피지), 백테스트 대비 성과 괴리, 오류 로그.

스케줄 예시 (cron, 서버 시간대 주의). 국장은 야후 지연(추정 20분)을 감안해 정각+21분, 미장은 봉이 매시 30분에 끝나므로 :31분.
첫 실행(국장 09:21, 미장 09:31)은 전날 마지막 봉 신호로 진입하는 회차, 마지막 실행(국장 14:21, 미장 15:31)은 장마감 청산 회차입니다.
```cron
# 국장: 평일 09:21~14:21 KST
21 9-14 * * 1-5 cd /path/to/autotrader && .venv/bin/python main.py trade --market kr >> logs/kr.log 2>&1
# 미장: 평일 09:31~15:31 ET (서버를 America/New_York 로 두거나 시각 변환)
31 9-15 * * 1-5 cd /path/to/autotrader && .venv/bin/python main.py trade --market us >> logs/us.log 2>&1
```
데이터 지연 때문에 실매매 체결 시각은 백테스트 가정(다음 봉 시가)보다 늦습니다. 예: 국장 장마감 청산은 백테스트에선 14:00 시가, 실매매에선 14:21에 나갑니다. 이 차이가 모의투자에서 확인할 핵심 항목입니다.

### 3단계 — 실전 판단
- 예시 기준: 모의투자 기간 동안 (a) 거래 50회 이상, (b) 비용 차감 누적손익·평균손익 모두 플러스, (c) MDD가 한도의 절반 이내, (d) 백테스트와 성과·거래 빈도가 크게 다르지 않음, (e) 운영 중 시스템 오류·누락 없음.
- 하나라도 못 미치면 실전으로 가지 않습니다. 모의투자는 체결이 실제보다 후할 수 있다는 점도 감안하세요.
- **이 저장소는 실전 주문을 지원하지 않습니다** (실전 서버·실전 tr_id를 코드에서 거부). 실전 전환은 공식 문서로 실전 도메인·tr_id를 확인하고, 손절 감시 주기 등 아래 한계를 보완한 뒤 소액으로 별도 진행하세요.

## 일봉 ETF 프로필 (100만원 · 다음 날 시가 주문)

### 왜 이 구성인가
- **1시간봉 ML 은 비용을 못 넘었습니다.** 표본 외 AUC 국장 0.569 · 미장 0.530, 비용 차감 전 거래당 평균이 국장 +0.002% · 미장 −0.07% 로 사실상 0 → 왕복 비용(국장 0.25%)만큼 계속 잃는 구조였습니다.
- **거래를 줄이고(일봉, 연 25회 안팎) 비용이 싼 상품으로**: 국내 주식형 ETF 는 매도 거래세가 없습니다.
- **100만원**이면 대형주는 1~2주라 분산이 안 됩니다 → 시장 대표 2개 + 업종 7개 ETF 중 최대 3개, 1개당 약 33만원.
- **시가 주문**: 전날 종가로만 판단하므로 장중 감시가 필요 없습니다. 08:30~09:00 동시호가에 넣고 09:00 단일가로 체결됩니다.
- 파라미터(200일선 · 20일 돌파 · 20일선 청산 · −8% 손절 등)는 결과를 보기 **전에** 정했고, 아래 결과를 보고 고치지 않았습니다.

### 규칙 (`config.daily.yaml`)
| 항목 | 값 | 동작 |
|---|---|---|
| 진입 | `long_ma` 200 · `breakout_lookback` 20 | 종가 > 200일선 **그리고** 종가 > 직전 20거래일 최고 종가(당일 제외) → 다음 날 시가 매수 |
| 매수 주문 | `entry_limit_pct` 2.0 | 지정가 = 신호일 종가 × 1.02 (호가단위로 내림). 시가가 더 높게 시작하면 미체결 → 취소, 따라 사지 않음 |
| 청산 | `exit_ma` 20 | 종가 < 20일선 → 다음 날 시가 매도 |
| 손절 | `stop_loss_pct` 8 · `stop_check: close` | 종가가 매수가 대비 −8% 이하 → 다음 날 시가 매도 (갭하락이면 더 잃음) |
| 종목 수 | `max_positions` 3 · `position_size_pct` 33 | 최대 3종목, 1종목 = 평가금액의 33%. 후보가 넘치면 20일 수익률 높은 순 |
| 재진입 | `reentry_cooldown_bars` 5 | 판 종목은 5거래일 동안 다시 사지 않음 |
| 계좌 한도 | `max_drawdown_pct` 10 | 계좌 고점 대비 −10% → 전부 매도하고 중단 (재개: 원인을 확인한 뒤 `trade --resume`) |
| 비용 | 수수료 0.015%(가정) · 매도세 0 · 슬리피지 0.02% | 왕복 0.07%. 본인 계좌 수수료로 고치세요 |

### 실행
```bash
python main.py --config config.daily.yaml fetch      # 일봉 10년치
python main.py --config config.daily.yaml backtest   # 결과표 + 같은 기간 비교 · 연도별 · 국면별
python main.py --config config.daily.yaml signal     # 다음 거래일 주문표 (보유 없음 가정)
python main.py --config config.daily.yaml signal --held 069500@105000,091160 --equity 1020000
#   --held   보유 종목: 코드 또는 코드@매수가, 쉼표로 구분 (매수가에는 쉼표 금지). 매수가를 주면 −8% 손절도 판단
#   --equity 현재 계좌 평가금액(원). 1종목 예산 = 평가금액 × 33%
python main.py --config config.daily.yaml trade --market kr   # 가상계좌 정산·계획 (DRY_RUN 기본) — 아래 'trade' 참고
python main.py --config paper/config.yaml summary              # 가상계좌 운영 요약 (같은 기간 KODEX 200 보유와 비교)
```
설정 파일은 `base: 다른설정.yaml` 로 상속할 수 있습니다 (dict 는 키 단위로 덮어씀, 상대 경로는 그 파일 폴더 기준). `paper/config.yaml` 이 예입니다.
`signal`은 상태가 없는 주문표(보유를 직접 알려줌), `trade`는 가상계좌가 보유·현금·재진입 대기·계좌 낙폭을 기억하며 매일 이어 가는 방식입니다.

### trade — 가상계좌(DRY_RUN) · 모의투자(DRY_RUN=false)
**가상계좌 (기본, 증권사 계좌 필요 없음)**: 평일 **16:30 이후 하루 한 번** 실행합니다.
1. 어제 계획한 주문을 오늘 **시가**로 정산합니다 — 백테스트와 같은 규칙(매도 먼저, 시가가 지정가보다 높으면 매수 미체결).
2. 오늘 종가로 평가하고 계좌 낙폭(−10%)을 확인한 뒤, 손절·청산·진입을 계획해 **다음 거래일 시가 주문**으로 저장합니다.
3. 며칠 빼먹어도 밀린 거래일을 순서대로 처리하고, 같은 날 두 번 실행해도 중복 처리하지 않습니다.
   한 종목이라도 데이터 수집에 실패하거나 최신 일봉이 늦게 들어오면(3거래일 이내) 그날은 처리하지 않고 기다렸다가 다음 실행 때 함께 처리합니다
   — 그날을 빠뜨리면 백테스트와 달라지기 때문입니다. 3거래일 넘게 새 일봉이 없는 종목은 거래정지로 보고 기다리지 않습니다.
4. 기록: `state/daily_kr_paper_state.json`(보유·현금·대기 주문), `..._journal.csv`(체결), `..._equity.csv`(일별 평가금액).
   테스트로 **"가상계좌를 매일 돌린 체결 = 같은 기간 백테스트의 체결"** 을 확인합니다 (낙폭 중단·손절·지정가 미체결·현금 부족 경우 포함).

계좌 낙폭 한도로 멈췄다면 원인을 확인한 뒤 `trade --market kr --resume` 으로 재개합니다 (고점 기준을 그때 평가금액으로 다시 잡음).

출력의 "다음 거래일 시가 주문"을 미래에셋 MTS 에 그대로 넣으면 실계좌를 가상계좌와 같게 운용할 수 있습니다 (시작 금액이 같다는 전제: `initial_capital`).

**모의투자 (한국투자증권, `.env` 에서 사람이 직접 `DRY_RUN=false` 로 바꾼 경우만)**: 하루 두 단계, 시계로 단계를 고릅니다.

| 시간 (평일 KST) | 단계 | 하는 일 |
|---|---|---|
| 08:30~09:00 | 주문 | 전 거래일 종가 기준 매도(시장가)·매수(지정가 = 종가+2%, 호가단위 내림). 현금이 모자란 매수는 '매도 대금 대기'. 같은 날 다시 실행해도 재주문 안 함 |
| 09:02~15:20 | 확인 (여러 번 실행 가능, 09:00 체결이 조회에 잡히도록 2분 뒤부터) | 일별 체결조회 → 매수 체결분 기록(손절가 = 체결 평균가 −8%) · 남은 매수 잔량 취소 · 동시호가에서 거부된 매도는 시장가로 1회 재시도 · 대기 매수는 오늘 시가 ≤ 지정가일 때만 같은 지정가로 주문 |
| 그 밖 | 조회 | 잔고 확인만 |

- 이 시스템이 연 포지션만 관리합니다. 계좌의 다른 보유 종목은 팔지도, 같은 종목을 더 사지도 않습니다.
- 빈자리·현금은 오늘 이미 낸 주문까지 반영해서 셉니다. 거부되거나 끝내 체결되지 않은 매도는 자리를 비우지 않습니다 (최대 종목 수를 넘겨 사지 않음).
- 기준가 조회가 일시적으로 실패한 종목이 있으면 그날 주문 단계를 끝난 것으로 기록하지 않습니다 → 09:00 전에 다시 실행하면 그 종목만 이어서 판단합니다 (이미 낸 주문은 다시 내지 않음).
- 매수 잔량 취소는 '취소 요청'으로 두고 다음 확인 때 체결조회를 다시 읽어, 취소가 닿기 전에 체결된 수량까지 포지션으로 기록합니다.
- 전 거래일 일봉이 없으면(공휴일 또는 데이터 지연) 증권사 **기준가**와 마지막 종가를 비교해 같으면 공휴일로 보고 진행, 다르면 그 종목은 그날 판단하지 않습니다.
- 지난 거래일에 확인하지 못한 주문은 다음 실행 때 체결 내역을 반영하고 나머지는 만료 처리합니다.
- 사용 API(공식 예제 기준): 주문 `order-cash`(VTTC0012U/0011U), 취소 `order-rvsecncl`(VTTC0013U), 일별 체결조회 `inquire-daily-ccld`(VTTC0081R, 연속조회), 현재가 `inquire-price`(시가 `stck_oprc`·기준가 `stck_sdpr`).
  정정취소가능주문조회는 모의투자용 tr_id 가 없어 주문 응답의 주문번호·주문조직번호로 직접 취소합니다.
- **확인 못 한 것**: 모의투자 서버가 08:30~09:00 동시호가 주문을 받는지 (공식 문서 접속 불가). 거부되면 09:00 이후 확인 단계에서 매도는 재시도, 매수는 대기로 넘어갑니다.
  이 경로는 가짜 증권사로만 테스트했고 실제 모의투자 서버에는 보내 보지 않았습니다.

### 주문표 → MTS 직접 입력
매 거래일 **16:00 이후**(장 마감 15:30 + 데이터 지연 30분) `signal`을 실행하면 다음 거래일 주문표가 나옵니다. 출력 예 (2026-10-01 종가 기준, 보유 2종목 가정):
```
[주문표] 평가금액 1,000,000원 기준 · 1종목 예산 330,000원 (33%) · 보유 2종목 → 매도 후 빈자리 2
매도 — 시가 동시호가, 시장가, 보유 전량
  - KODEX 자동차(091180.KS): 손절: 종가 25,455 ≤ 매수가 40,000의 -8% (36,800)
매수 — 지정가 (시가가 지정가보다 높으면 미체결 → 09:00 이후 취소, 따라 사지 않음)
| 종목                    |   지정가 |   수량 |    금액 |   예산 사용% | 근거                 |
| KODEX 반도체(091160.KS) |  152,600 |      2 | 305,200 |           92 | 점수 +20.0% · 순위 1 |
```
1. 08:30~08:59 에 주문합니다. **거래소는 KRX 로 지정**합니다 (통합·SOR 주문은 넥스트레이드로 갈 수 있음).
2. 매도는 시장가 → 09:00 시가에 체결됩니다.
3. 매수는 주문표의 지정가. 시가가 지정가보다 높으면 체결되지 않으니 09:00 이후 취소합니다 (백테스트도 '미체결 → 취소'로 계산).
4. 매수 자금이 같은 날 매도 대금이면 **매도 체결(09:00) 직후** 같은 지정가로 매수합니다. 동시호가 중에는 아직 팔리지 않은 대금이 주문가능금액에 잡히지 않습니다.
   백테스트는 같은 시가에 매도 대금으로 바로 산다고 가정하므로 여기서 작은 차이가 생깁니다.
5. 사람이 챙길 것: 판 종목 5거래일 재매수 금지, 계좌 고점 대비 −10% 면 전부 매도 후 중단, 공휴일 (프로그램은 주말만 건너뜀).
6. 정수 주식이라 1종목 예산을 다 못 씁니다. 2026-10 가격으로 KODEX 200(약 11만원)은 2주 = 예산의 약 68%, KODEX 반도체(약 15만원)는 2주 = 약 92%.

## 한계와 주의

- **봉 단위 판단**: 백테스트 손절은 봉 저가로, 실매매 손절은 사이클(1시간)마다 현재가로 확인합니다. 봉 중간 급락은 실매매에서 더 큰 손실이 될 수 있습니다. 실전 수준이면 더 짧은 주기 감시나 증권사 자동감시주문이 필요합니다.
- **데이터**: yfinance는 비공식 경로라 지연·누락·차단이 생길 수 있습니다. KRX 시세 지연 20분은 추정치(`data_delay_minutes`)입니다. 실매매에는 KIS 분봉 API로 바꾸는 것을 권합니다.

- **장 시간**: 주말만 건너뜁니다. 공휴일·조기폐장은 반영하지 않습니다 (백테스트는 실제 데이터 기준이라 영향 없음, 실매매는 증권사가 주문을 거부).
- **표본·편향**: 1시간봉 약 2년, 현재 대형주 6종목뿐이라 통계적 신뢰도가 낮고 생존 편향이 있습니다.
