# 가상계좌 자동 운영 기록

`config.daily.yaml`(국내 ETF 9종 · 100만원 · 추세 돌파) 규칙을 **실제 돈 없이** 앞으로 3개월 동안 돌린 기록입니다.
백테스트가 아니라 날마다 그날까지의 데이터만으로 정산·계획한 결과라 사후 조정이 없습니다.

| 항목 | 값 |
|---|---|
| 기간 | 2026-10-02 시작 → 2027-01-08 종료 (약 3개월) |
| 시작 금액 | 1,000,000원 (`initial_capital`) |
| 규칙 | `config.daily.yaml` 그대로 (이 폴더의 `config.yaml` 은 기록 위치만 바꿈) |
| 모드 | DRY_RUN (주문 전송 없음). 체결은 야후 일봉 시가 기준 |

## 파일
- `daily_kr_paper_state.json` — 보유·현금·다음 거래일 주문·재진입 대기·계좌 낙폭 상태
- `daily_kr_paper_journal.csv` — 체결 기록 (매수·매도·미체결)
- `daily_kr_paper_equity.csv` — 거래일별 현금·평가금액·고점 대비 낙폭

## 주간 점검 절차 (매주 토요일 오전, Claude 세션이 자동 실행)
1. 최신 `main` 을 받고 `python -m pytest` 가 전부 통과하는지 확인 (실패하면 기록하지 않고 원인만 보고)
2. `python main.py --config paper/config.yaml trade --market kr` — 지난 실행 이후 거래일을 순서대로 정산·계획
   - 데이터 수집 실패·지연이면 우회하지 않는다. 그날은 처리하지 않고 다음 실행 때 밀린 날로 처리된다
   - `DRY_RUN` 은 바꾸지 않고 `.env` 도 만들지 않는다
3. 매매 중단(계좌 낙폭 한도)이 걸렸으면 아래 정책대로 점검한다
4. `python main.py --config paper/config.yaml summary` 로 요약
5. 이 폴더의 변경만 커밋·푸시 (메시지: `가상계좌 주간 기록 YYYY-MM-DD`)
6. 종료일 이후 실행이면 최종 요약을 남기고 자동 실행을 끈다

## −10% 계좌 한도 정책 (2026-10-02 결정)
**결정**: 한도는 −10% 그대로 둔다. 다만 '영구 중단'이 아니라 **'멈추고 점검'하는 체크포인트**로 쓴다.

**근거**
- 백테스트에서 이 규칙의 정상 낙폭은 −33% 수준이라 −10% 한도는 몇 달 안에 걸릴 가능성이 높다 (2017년 시작 시 7개월째인 2018-02, 2010년 시작 시 6개월째 중단).
  그대로 '영구 중단'으로 두면 첫 조정에서 멈춰 규칙을 평가할 수 없다.
- 1종목 비중을 절반(16.5%)으로 줄이면 낙폭이 −17%로 줄지만 수익도 절반이 되고, 100만원에서는 1주 단위라 예산을 제대로 못 쓴다 (KODEX 200 약 11만원).
- 한도를 −35% 로 올리면 100만원 학습 계좌의 안전장치 의미가 없어진다.
- 100만원 중 10만원 손실 시점에 사람이 한 번 멈춰 점검하는 것은 학습 계좌의 목적(실수·버그를 일찍 발견)에 맞는다.

**점검 → 재개 기준** (모두 만족하면 `trade --market kr --resume`, 고점 기준을 그때 평가금액으로 다시 잡음)
1. 테스트가 전부 통과한다 (시스템이 규칙대로 동작)
2. 체결 기록에 이상이 없다 (그날 시가와 다른 가격의 체결, 빠진 날, 데이터 급변 없음)
3. 손실 원인이 규칙의 정상 범위다 (갭 하락·연속 손절 등). 시스템 오류였다면 고친 뒤 재개
하나라도 문제가 있으면 멈춘 상태로 두고 원인을 기록한다. 실계좌에서도 같은 기준을 쓴다.

## 끝난 뒤 판단 (실제 돈을 넣을지)
- 운영 중 시스템 오류·누락이 없었는가, 지정가 미체결이 백테스트(약 2%)보다 크게 많지 않은가
- 가상계좌 결과가 백테스트의 연도별 범위 안인가 (한 분기는 짧아 수익 크기로 판단하지 않는다)
- 이 규칙은 과거 9년간 KODEX 200 보유보다 수익이 낮았다(연 12.5% vs 16.7%). 이를 받아들일 때만 소액으로 시작한다
